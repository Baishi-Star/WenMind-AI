# WenMind AI 决赛答辩 PPT 大纲（12 页）

> 每页含要点与**需补充的真实材料占位**；截图/数据一律不得合成，见 `../codedao_proof/` 清单。

## 第 1 页 · 封面
- 项目名：WenMind AI（文思智评）
- 一句话定位：让每一次作文评价都成为下一次写作成长的起点
- 版本：v1.0.0（决赛交付）
- 占位：项目 Logo（使用仓库内 `frontend/public/favicon.svg`）／团队信息待填

## 第 2 页 · 痛点
- 作文评价耗时、反馈笼统，学生难以据此改进
- 评分依据不透明，学生有异议时缺乏可追溯证据
- 教师复核多为口头结论，难以沉淀为可复用规则

## 第 3 页 · 方案总览
- 目标闭环：可解释 → 可质疑 → 可复核 → 可持续改进
- 三类使用者：学生、教师、管理员
- 占位：可替换为产品首页真实截图

## 第 4 页 · 系统架构
- 前端：Vue 3 + Vite + Element Plus + Pinia + Vue Router + ECharts
- 后端：FastAPI + SQLAlchemy 2.0 + SQLite（35 张表）
- 模型与检索：OpenAI-compatible 模型 + 本地 FAISS／远程 Embedding
- 占位：架构图可用文字转绘，需标注为示意图

## 第 5 页 · 核心机制一 · 多 Agent 协同评价
- 链路：审题 → 内容 → 表达 → 发展 → 综合反馈 → 质量审核 → 证据核验
- 结构化输出经 Pydantic 校验，失败有限重试；推理模型截断有明确兜底
- 占位：评价过程页真实截图

## 第 6 页 · 核心机制二 · 证据核验与总分口径
- 三维 0–20（内容／表达／发展），审题保留但不计分
- 60 分制总分按量规基准校准合成，公开 `raw_total` 与校准参数
- 少于 3 篇评价显示“数据积累中”，趋势不使用随机数
- 占位：AI 评价报告页真实截图（含校准说明）

## 第 7 页 · 核心机制三 · 申诉与教师复核
- 学生申诉 → 教师复核 → 争议归因 → 统计 → 规则建议审批 → 版本发布
- 双轨保存：AI 原始分与教师最终分互不覆盖，`final_total_score` 联动写入
- 占位：教师复核工作台真实截图
